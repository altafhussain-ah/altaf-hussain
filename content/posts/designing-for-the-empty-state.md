Open any product's Figma file and you'll find forty screens full of data and, if you're lucky, one sad grey box labelled "empty".

This is backwards. The full state is what users see on day four hundred. The empty state is what they see on day one — the only moment they're still deciding whether to stay.

## Empty is not one state

There are at least four, and they want different things:

1. **First run.** Nothing exists yet because nothing *could* exist yet. This is onboarding wearing a disguise.
2. **Cleared.** The user finished everything. This deserves congratulation, not an error-grey illustration.
3. **No results.** A filter or search excluded everything. The fix is almost always "widen or clear the filter" — so say that, and put the button right there.
4. **Failed.** Something broke. Be specific about what, and what happens next.

Shipping one component for all four is how you end up telling someone who just completed every task that there's "nothing to see here."

## What a good empty state does

It answers three questions without being asked: *what goes here*, *why is it worth putting something here*, and *what do I press*.

That last one matters more than the copy. An empty state with a paragraph and no button is a dead end with good manners.

## The cheapest version that works

If you have no design budget at all: one sentence of plain description, one primary action, and — where you can manage it — a faint preview of what the filled version will look like. Skip the illustration. Nobody ever stayed for the illustration.
